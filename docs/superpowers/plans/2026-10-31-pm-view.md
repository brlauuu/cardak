# PM view Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A PM view in the deck (`P` all projects, `p` one project) and on the phone: per project, every open issue (todo), work in progress (onit) and an LLM summary of the last 7 days (done), read from GitHub through `gh` only while the deck runs.

**Architecture:** `collectors/github.py` is the one `gh` interface (GraphQL); `collectors/git.py` gains branch and remote reads. `core/pm.py` builds the board (pure), `core/pm_done.py` writes the done column (summarizer, cap, cost row), `core/pm_service.py` runs a thread in the deck that decides when to fetch, keeps a per-repo cache and writes the board file. `ui/pm.py` draws layout A; the daemon serves the board file at `/api/pm` and the page gets a Projects sheet.

**Tech Stack:** Python 3.13, Textual, SQLite, `gh api graphql`, stdlib JSON; vanilla JS in `web/page.html`.

**Spec:** `docs/superpowers/specs/2026-10-31-pm-view-design.md`

## Global Constraints

- Layering: `collectors/*` import nothing from cardak; `core` never imports `ui`, `web`, `llm`; `cli.py` hands the summarizer factory over (`ProviderTools`).
- All `gh` invocation and parsing lives in `collectors/github.py`; git reads stay in `collectors/git.py` (`git --no-optional-locks`, timeout).
- Tests never run `gh`, git on real repos, the network or a real provider: inject runners; recorded GraphQL replies in `tests/fixtures/github/` with made-up repos (`example/webshop`).
- No writes to GitHub. Nothing new in `cardak hook` (its 150 ms budget and import guards stay).
- GitHub is read only by the deck: at start when the cache is older than 60 min, every 60 min, on `R`, and after a Claude session ran `gh issue …`, `gh pr …`, `gh release …`, `git push` or an `mcp__github*` tool.
- A done summary is written only when its input changed; it is an expense: recorded in a new table, counted by `Store.spend_since`, refused at `[summary] monthly_limit_usd`. New table only: `MIN_READER` stays 1, `SCHEMA_VERSION` 6 → 7.
- Issues closed as `NOT_PLANNED` are left out of done.
- Errors are one readable line in the band; last good data stays with its age. Copy: "gh isn't installed", "can't reach GitHub", "not on GitHub", "Nothing done this week."
- Web: Bearer like the other `/api/*`; only `https://github.com/` URLs go out; text via `textContent`; no `style=` attributes.
- Public repo: no personal paths or names in code, fixtures, commits.

## Review Focus

1. A repo with no issues, no PRs, nothing done: every column renders its empty state, no crash (test in Task 3).
2. `gh` logged out / offline after a good fetch: band keeps the old cards, shows the error and the old fetch's age (test in Task 5).
3. A branch like `release-0.15.0`, `v2-redesign`, `fix/2024-cleanup` must not claim issue #0, #2 or #2024 unless that is the leading number by the rule (test in Task 3).
4. A done reply citing a PR number it wasn't given, or with no bullets at all: invented refs dropped, all-invalid falls back to the list (test in Task 4).
5. A label color that isn't 6 hex digits, or a URL not on github.com, from the board file: the phone gets no color / no link (test in Task 7).

### Task 3: Core board — todo, onit, PR cards, sessions

**Files:**
- Create: `src/cardak/core/pm.py`; Test: `tests/test_pm.py`

**Interfaces:**
- Consumes: Task 2's `RepoData`, `Issue`, `PullRequest`, `Label`; `core.agents.Status`.
- Produces:
  - `issue_number(branch: str) -> int | None` — the number at the start of the branch or right after its last `/`, followed by `-`, `_` or the end: `re.match(r"(\d+)(?:[-_]|$)", branch.rsplit("/", 1)[-1])`, and only if `> 0`.
  - `Card(kind: Literal["issue", "pr"], number: int, title: str, labels: tuple[Label, ...], updated_at: float, url: str, branch: str | None = None, pr: int | None = None, session: Status | None = None)`
  - `Bullet(text: str, refs: tuple[int, ...], url: str | None)`; `Done(bullets: tuple[Bullet, ...], note: str | None)` — `note` is the dim line (why it's a plain list, or "Nothing done this week.").
  - `Band(name: str, path: str, repo: str | None, todo: tuple[Card, ...], onit: tuple[Card, ...], done: Done, fetched_at: float | None, error: str | None)`
  - `Board(bands: tuple[Band, ...], built_at: float)`
  - `build_band(name: str, path: str, repo: str | None, data: RepoData | None, local: Sequence[str], sessions: Mapping[str, Status], done: Done, fetched_at: float | None, error: str | None) -> Band` — `local`: the project's branch names; `sessions`: branch → state of a live Claude session on it (the most urgent when several: waiting > working > idle).
  - `board_to_json(board: Board) -> dict[str, object]`; `board_from_json(data: object) -> Board | None` (None on any shape problem).
  - `NOTHING_DONE = "Nothing done this week."`; `NOT_ON_GITHUB = "not on GitHub"`

Rules for `build_band`: an issue is onit when a local branch or an open PR's branch has its number, or an open PR closes it; its card gets `branch` (a local one first, else the PR's) and `pr` (the lowest open PR number that closes or names it). Open PRs that claim no open issue become `kind="pr"` cards in onit. todo = the other issues. Both columns sorted by `updated_at` descending (PR cards by their own). `session` = `sessions.get(card.branch)`. `repo is None` → empty columns, `error=NOT_ON_GITHUB`.

### Task 4: Core done column — prompt, parse, fallback, cost

**Files:**
- Create: `src/cardak/core/pm_done.py`; Test: `tests/test_pm_done.py`

**Interfaces:**
- Consumes: Task 1's `PmSummaryRow`, `Store.add_pm_summary`, `Store.spend_since`; Task 2's `RepoData`; Task 3's `Done`, `Bullet`, `NOTHING_DONE`; `core.summary.{cost, provider_key, KeyProblem, month_start, Summarizer}`, `core.config.{SummarySettings, summary_ready}`, `core.summary.ProviderTools`.
- Produces:
  - `DONE_SYSTEM_PROMPT: str` — asks for at most `MAX_BULLETS = 6` lines, each starting `- `, plain language for the developer, each ending with the numbers it covers in parentheses, `(#203, #204)`, using only numbers given.
  - `done_input(data: RepoData) -> str` — one line per item, oldest first: `PR #203 merged: <title> (closes #198)` / `Issue #150 closed: <title>`.
  - `done_hash(data: RepoData) -> str` — sha256 of `done_input`.
  - `parse_done(text: str, data: RepoData) -> tuple[Bullet, ...]` — bullets from `- ` lines; refs = `#N` in the line that are among the given PR/issue numbers; bullets with no valid ref dropped; text stripped of the trailing ref parentheses, cut at `MAX_BULLET = 160`; `url` = the first ref's URL; at most `MAX_BULLETS`.
  - `fallback(data: RepoData, note: str | None) -> Done` — one bullet per merged PR (`title`, `(pr,)`, url), then closed issues no PR closes; empty → `Done((), NOTHING_DONE)`.
  - `write_done(repo: str, data: RepoData, now: float, *, summary: SummarySettings, keys_dir: Path, tools: ProviderTools, store: Store) -> tuple[Done, bool]` — the `bool` is "settled": True when the result may be cached under this input's hash (a summary, or nothing to summarize), False when it should be tried again at the next fetch (not ready, cap reached, failure).

Notes (copy fixed here): not ready → `fallback(data, "summaries are off: set one up with s")`; cap reached → `fallback(data, "monthly summary cap reached")`; provider error → record `PmSummaryRow` with cost 0 and `error`, `fallback(data, "the summary failed: <first 80 chars>")`; reply with no valid bullet → record its cost, `fallback(data, "the summary couldn't be used")`, settled True. Nothing merged or closed → `Done((), NOTHING_DONE)`, no call, settled True.

### Task 5: Core service — when to fetch, cache, board file

**Files:**
- Create: `src/cardak/core/pm_service.py`; Test: `tests/test_pm_service.py`

**Interfaces:**
- Consumes: Tasks 1–4; `collectors.hooks.parse`; `core.config.{Config, Project, cache_dir, state_dir}`.
- Produces:
  - `REFRESH_EVERY = 3600.0`, `TRIGGER_DELAY = 15.0`, `MIN_GAP = 60.0`, `LOCAL_EVERY = 10.0`, `EVENTS_EVERY = 5.0`, `DONE_DAYS = 7`
  - `board_path(env=None) -> Path` = `state_dir(env) / "pm.json"`; `repo_cache_dir(env=None) -> Path` = `cache_dir(env) / "github"` (one `<owner>__<repo>.json` per repo: fetched_at, the RepoData, error, done, done_hash).
  - `changes_github(payload: str) -> bool` — parsed with `hooks.parse`; True for `tool_name == "Bash"` and a command matching `\bgh\s+(issue|pr|release)\b` or `\bgit\s+push\b`, or `tool_name.startswith("mcp__github")`.
  - `class PmService:` `__init__(self, config: Callable[[], Config], store: Store, *, keys_dir: Path, tools: ProviderTools | None, fetch: Callable[[str, float], RepoData], git_runner: Runner, board_file: Path, cache: Path, clock: Callable[[], float] = time.time)`
    - `observe(self, sessions: Sequence[tuple[Path, Path | None, Status]]) -> None` — (project path, session cwd, state) from the deck's latest snapshot; thread-safe.
    - `refresh(self, project: Path | None = None) -> None` — `R`: one project or all, due now (still at most once per `MIN_GAP` per repo).
    - `board(self) -> Board | None` — the latest, thread-safe.
    - `step(self) -> None` — one tick: re-read local branches and session branches every `LOCAL_EVERY`; scan `store.tool_events_after(watermark)` every `EVENTS_EVERY` and make a project due at `ts + TRIGGER_DELAY` when `changes_github` and `ts > ` its repo's `fetched_at`; fetch every due repo (sequentially) — due when no cache, cache older than `REFRESH_EVERY`, or requested; on success write the cache, run `write_done` when `done_hash` changed or the cached done wasn't settled; rebuild the board; write `board_file` atomically when it changed.
  - `background(service: PmService, log: Callable[[str], None]) -> threading.Event` — runs `step` every 1 s on a daemon thread until the event is set; an exception in `step` is logged and the loop goes on.

Projects come from `config().projects`, in order; repo = `project.github` or `repo_from_url(remote_url(path))`. Projects sharing a repo share one fetch and cache entry. A session's project is the one whose path the deck put it under (the `observe` tuple), so the store's cwd isn't re-resolved; for events the payload's `cwd` is matched to the project whose path contains it.
